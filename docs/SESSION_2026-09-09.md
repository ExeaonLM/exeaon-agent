## 1. Cloud + API models were totally broken — FIXED (root cause: session key)

Symptom: every model (cloud Exeaon-* AND custom Deepseek) failed to send —
"missing credentials" / "missing or invalid Authorization header" / "all
upstream providers failed".

Root cause cascade (all fixed):
1. **`OH_SECRET_KEY` is dual-use** — it both authenticates agent-server requests
   AND encrypts every stored `api_key` at rest (Fernet). A prior change made it a
   per-install RANDOM key; that orphaned every previously-saved key (they no
   longer decrypted → `None`). **Fix (`lib.rs`): reverted to a stable secret.**
   Per-install hardening can return ONLY with a legacy→current re-encryption
   migration first — see `[[exeaon-cloud-connection-facts]]`.
2. **Sovereign-key fallback was unscoped** — `sk-exeaon` was injected for ANY
   empty key, so Deepseek got `sk-exeaon` (invalid). Scoped via `isSovereignLLM`
   + `resolveSovereignApiKey`: gateway models use the user's `sk-vk-*` virtual
   key (the gateway REJECTS anything not `sk-vk-`), custom providers keep their
   own key. Applied in conversation-start AND `switchLLM`.
3. **Cloud model names drifted** — the app sent `Exeaon-Spark-1.0` (hyphens) but
   the gateway registers `Exeaon Spark 1.0` (spaces) → no match → "all upstream
   providers failed". Fixed `DEFAULT_CLOUD_MODELS` to the gateway's exact names;
   sync force-mints a fresh `sk-vk-*` and re-saves the cloud profiles.

Commit: `e2a523c75`. Diagnosis was empirical — queried the live gateway (healthz,
`/ai/v1/models`, `/ai/gateway/providers`) via `flyctl ssh`, and drove
`/ai/v1/chat/completions` with the user's virtual key to see the exact upstream
error. Gateway providers: Exeaon Aeon/Spark/Arc → DeepSeek, Vision → DeepSeek
vision, Video → OpenRouter.

**Usage windows read 0%** because the gateway only meters traffic through it
(`me.go` sums the audit log + daily rollup per virtual key); until this fix no
cloud inference reached the gateway. It should populate now; if not, check the
key's `created_by`.

## 2. Viewer + chat UX

- **Viewer consolidation** (`4debc19bc`): the research war-room and the cyber
  operative graph are now ONE field-adaptive right-panel tab — research → 🔬
  war-room, cyber/default → Network graph (icon/label follow the field).
  Robotics/RTL keep their own tabs. The standalone Research tab was removed.
- **War-room pairing fix** (`7a85bfa84`): it filtered observations by
  `tool_name` — but an OBSERVATION carries no `tool_name` (it's on the paired
  ACTION event, referenced by `action_id`). Now it maps research-tool action ids
  then reads the observations answering them (mirrors the swarm viewer). NOTE:
  robotics/rtl viewers still read `observation.tool_name` — latent, patch if
  their panels look empty while the sim runs.
- **Scroll on open** (`fa8ced542`): opening an old conversation replayed a
  top-to-bottom scroll. The one-shot pre-paint pin lost the race as heavy content
  (markdown/tool-viz/images) grew height over many frames. Now a
  `requestAnimationFrame` settle loop (in a ref, so it survives the effect
  re-running on streamed events) keeps it glued to the bottom for ~1.5s, bailing
  if the user scrolls up. **UNVERIFIED — needs a reload-check.**

## 5. LLM-as-judge — BUILT (`research-judge` subagent + record_judgment)

An INDEPENDENT `research-judge` subagent (`model: inherit`; seeded from
`resources/subagents/research-judge.md`) is summoned at the verification gate to
grade the manuscript against the claims + sources — per-claim supported /
overstated / unsupported + `groundedness` and `faithfulness` scores. The lead
records the verdict via the research MCP's `record_judgment`, which folds into
the composite integrity grade and shows a "Judge G% · F% faithful" chip in the
war-room. Self-contained (no NVIDIA AIQ runtime / keys / sidecar). AIQ's profiler
could still layer on later for cost/latency telemetry.
